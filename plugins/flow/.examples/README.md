# Flow sample output

These files are sample outputs for one fictional card, `PROJ-1234`. They show
what each Flow sub-agent writes into a card folder. Nothing here is loaded by
the plugin, and the ticket, decisions, and verdicts are invented for the
example.

## Files

| File | Generated by | What it does | Example command |
|---|---|---|---|
| [feature/PROJ-1234/decision-log.md](feature/PROJ-1234/decision-log.md) | decision-logger | Records the decisions behind the card, one row each, with owners and notes. | `/flow:decisions PROJ-1234` |
| [feature/PROJ-1234/p01/spec.md](feature/PROJ-1234/p01/spec.md) | spec-author | The spec for pass 1: problem, goals, acceptance criteria, constraints, and database prerequisites. | `/flow:spec PROJ-1234` |
| [feature/PROJ-1234/p01/validation.md](feature/PROJ-1234/p01/validation.md) | test-planner | The test plan: risk level, impacted workflows, conditional logic, and TS-### scenarios. | `/flow:test PROJ-1234` |
| [feature/PROJ-1234/p01/front-end-testing.md](feature/PROJ-1234/p01/front-end-testing.md) | test-planner | A manual guide a tester can follow in the running app, with pass/fail checkboxes. | `/flow:test PROJ-1234` |
| [feature/PROJ-1234/p01/spec-testing.md](feature/PROJ-1234/p01/spec-testing.md) | test-planner | Maps each acceptance criterion to the scenarios that cover it. | `/flow:test PROJ-1234` |
| [feature/PROJ-1234/p01/code-review.md](feature/PROJ-1234/p01/code-review.md) | code-reviewer | Severity-ranked review findings with file and location, plus the clean files. | `/flow:review PROJ-1234` |
| [feature/PROJ-1234/p01/acceptance-criteria.md](feature/PROJ-1234/p01/acceptance-criteria.md) | ac-verifier | Pass, partial, fail, or manual verdict for each acceptance criterion, with evidence. | `/flow:verify PROJ-1234` |
